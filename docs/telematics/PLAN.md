# GPS и топливо в кабинете перевозчика — план (ред. 2, 28.10.2026)

Статус: **топливо (разделы 3.1, 3.2, 3.4) сделано 28.10.2026**, GPS отложен до запроса перевозчика. **[решить]** — решения за пользователем.

**Решения пользователя от 28.10.2026:**
- Упор на небольшие компании. Машины часто старые, но у многих уже стоит GPS-трекер, поэтому подключаемся **к их провайдерам**, а не к производителям грузовиков.
- Топливо считаем тремя способами по нарастающей точности:
  1. перевозчик загружает месячный отчёт заправщика;
  2. водитель вносит каждую заправку (как в LogiApp): пробег, литры топлива или газа, AdBlue;
  3. подключение кабинета топливной карты — лучше и точнее всего.

- **Деньги: всё входит в подписку 29,90 € за машину**, включая GPS, топливо, аналитику и CO₂. Платформа **ничего не тратит**: никаких платных сервисов-посредников и платных партнёрских программ. Если провайдер берёт плату за доступ к своему API, это договор перевозчика с его провайдером, а не наш.

Проверка рынка со ссылками: `research-providers.md`. Заводской стандарт rFMS (`research-rfms.md`) — запасной путь для новых машин.

## 1. Что это даёт

- **Заказчику:** где машина сейчас, ETA, автоматические «прибыл/убыл», простой подтверждён треком.
- **Самосвалам:** прибытие на объект и конец дня по геозоне.
- **Перевозчику:**
  - расход каждой машины (л/100 км) и стоимость топлива на км;
  - стоимость топлива на рейс, маржа рейса;
  - сравнение машин и водителей;
  - подозрительные заправки.
- **Заказчику-корпорации:** CO₂ по рейсам (CSRD / Scope 3). Входит в подписку и служит аргументом для заказчика выбрать перевозчиков RAHTIS.

## 2. GPS: подключение к провайдеру перевозчика

### 2.1 Провайдеры, где клиент сам выдаёт нам ключ (фаза 1)

| Провайдер | Как подключается | Что даёт | Заметки |
|---|---|---|---|
| **Mapon** (LV, популярен в Балтии и FI) | администратор клиента создаёт API-ключ (Settings → API keys), ключ можно ограничить по машинам | позиция, скорость, **пробег**, топливо/CAN (часть методов платная), push через Data_forwarding | самый простой старт |
| **ABAX** (NO, крупный в Скандинавии и FI) | Open API, OAuth; client_id выдаёт ABAX Developer portal, есть sandbox, production по заявке | машины, поездки, **одометр** | **написать в ABAX** о партнёрском доступе |
| **Navirec** (EE) | клиент создаёт токен (API access → Add new token) и даёт права «See location» | позиции | доля в FI не подтверждена |
| **GpsGate** | администратор генерирует REST-токен | последняя позиция и сигналы | |
| **Frotcom** | логин клиента → api_key; webhooks с позициями | позиции push | токен живёт 20 мин без активности |
| **Webfleet** | клиент запрашивает ключ в My Account, мы вступаем в .connect Partner Program | позиции, одометр, очереди сообщений | лимиты строгие, цена по запросу |

**Через партнёрство или контакт (фаза 2):** Vehco/AddSecure (бывшая финская Paetronics, тяжёлые грузовики) и Ecofleet/Fleet Complete. Публичного API у них нет, нужно писать напрямую.

### 2.2 Длинный хвост: мелкие финские реселлеры трекеров
- **Второй сервер на трекере.** У Teltonika есть режим Duplicate: каждая точка уходит и провайдеру, и нам, сам провайдер ничего не теряет. Конфигурацию трекера обычно держит реселлер, поэтому перевозчик просит его добавить наш адрес. Мы даём готовый текст письма.
- **Пересылка из Wialon** (Retranslator / Wialon IPS). На Wialon работают многие мелкие реселлеры, у них пересылка на сторонний сервер включается в настройках.
- **Приёмник — свой, без flespi** (платформа ничего не тратит). Протоколы Teltonika Codec 8 и Wialon IPS — это TCP, а Vercel принимает только HTTP, поэтому нужен маленький постоянно работающий сервис. Варианты:
  - **[решить]** на уже оплаченном сервере (UpCloud, где демо), если там есть запас;
  - или бесплатный тариф хостинга.
  
  Сервис только принимает точки и передаёт их в Supabase. Этот этап идёт после провайдеров с API.
- **Запасной вариант:** GPS телефона в приложении водителя, только во время рейса.

### 2.3 Устройство
- **Адаптеры.** У каждого провайдера свой адаптер с общим интерфейсом: `listVehicles()`, `positionsSince(t)`, `odometer()`. Опрос раз в 2–5 мин только для машин на активном рейсе или объекте; push-источники (Mapon forwarding, Frotcom webhooks, flespi) пишут сразу.
- **Экран «GPS-seuranta» в кабинете перевозчика:**
  - выбрать провайдера, вставить ключ;
  - сопоставить машины провайдера с машинами RAHTIS по номеру;
  - видеть, когда пришла последняя точка.
  - Для хвоста — инструкция и письмо реселлеру.
- **Данные:**
  - `gps_connections` — company_id, provider, статус, последняя точка, ошибка. **Ключ хранится в Supabase Vault**, это первое использование Vault в проекте.
  - `vehicles.gps_connection_id` и `gps_external_id`.
  - `vehicle_track` — пишется **только во время рейса, дня на объекте или смены**.
  - `odometer_readings` — источник GPS / водитель / заправка.
- **Автособытия** (фаза 3):
  - прибытие по геозоне точки рейса (ручная отметка водителя главнее);
  - день на объекте;
  - ETA по треку.

## 3. Топливо: три способа, одна таблица

Все способы пишут в одну таблицу `fuel_entries`:
- машина, водитель;
- время, место или станция;
- продукт и количество в своих единицах;
- цена и сумма без и с ALV;
- одометр;
- фото чека;
- источник `IMPORT | DRIVER | CARD_API`;
- ссылка на исходную строку.

Одна заправка из разных источников сливается в одну запись: совпадение по машине, времени ±30 мин и объёму ±2 %. Приоритет у карты, у водителя берётся одометр.

**Продукты:**
- diesel, HVO100 / Neste MY, AdBlue — в **литрах**;
- LNG, LBG, CNG, CBG — в **кг**;
- «прочее».

Единица хранится у каждой записи.

### 3.1 Загрузка месячного отчёта (фаза 1)
- Перевозчик загружает CSV или XLSX из кабинета заправщика. Это Neste (CSV по заправкам) и St1/Shell (Fleet Hub Online); дальше Teboil, ABC, DKV, UTA, Circle K (SE/NO/DK).
- **Импорт с сопоставлением колонок.** Для известных форматов шаблон готов. Для неизвестных перевозчик один раз указывает, где какие колонки, и шаблон запоминается для компании.
- **Машина определяется** по номеру из отчёта или по карте. Связь «карта → машина» запоминается.
- Проверка перед сохранением: показываем, что распознано и что не привязано, повторная загрузка того же отчёта не дублирует строки.
- PDF-отчёты — позже, через распознавание (n8n + OpenAI, как задумано для талонов весов).

### 3.2 Ввод водителем при заправке (фаза 1)
- Кнопка «Tankkaus» в приложении водителя, работает и без сети (через существующий outbox):
  - одометр;
  - продукт и количество (можно несколько строк: дизель + AdBlue);
  - сумма (необязательно);
  - фото чека и одометра.
- Подсказки против ошибок:
  - одометр меньше прошлого или прыжок больше 3000 км;
  - объём больше бака машины (нужно поле `tank_l` у машины).
- Опционально распознавание чека по фото — заполнит литры и сумму.

### 3.3 Подключение кабинета топливной карты (фаза 2)
API подтверждены:
- **DKV** — Enterprise API, technical user через отдел продаж;
- **Circle K** — Transactions API: SE, NO, DK;
- **Shell** — Transaction Data API, отдаёт одометр, если на карте включён ввод пробега; применимость к финским картам St1/Shell **не проверена**.

**Neste:** публичного API нет, но у Mapon есть ежедневная интеграция с Neste, значит доступ получить можно. **Написать в Neste.**

### 3.4 Аналитика (фаза 1–2)
**Расход на машину за период:**
- л/100 км: топливо между двумя полными заправками, делённое на пробег по одометру; GPS-пробег — как проверка;
- €/км, AdBlue в % от дизеля;
- тренд по месяцам, сравнение машин и водителей.

**Подозрительное:**
- заправка, когда машина по GPS была далеко от станции;
- объём больше бака;
- две заправки подряд;
- резкий рост расхода.

**Для рейсов:**
- стоимость топлива на рейс = км рейса × €/км машины за месяц;
- маржа рейса в кабинете перевозчика;
- CO₂ рейса — расход × коэффициент продукта (HVO и биогаз дают меньше). Коэффициенты брать из GLEC / ISO 14083, **не проверены**.

## 4. Приватность и право (в той же задаче, что и код)
- Непрерывный трек и заправки по водителю — новые категории данных. Правим PRIVACY 2.4 / 7.1 / 8.4 черновой миграцией и purge.
- **Срок хранения [решить].** Предлагаю:
  - трек — 90 дней;
  - итоги рейса и заправки — 24 мес. (заправки — бухгалтерские данные, возможно, дольше: уточнить).
- **Кто видит:**
  - заказчик — позицию своего рейса, пока он идёт, и итог;
  - топливо и маржу видит только перевозчик и оператор.
- **Роли по GDPR:** для своих водителей ответственный за обработку данных — перевозчик, RAHTIS обрабатывает их по его поручению (DPA).
- **yhteistoimintalaki:** перевозчику нужен шаблон уведомления водителям (fi/sv/en). Вне рейса трек не собираем.
- Ключи провайдеров — только в Vault. Перевозчик может отключить их в любой момент.
